# CoachTrack

Учебное Fullstack-приложение для тренера и спортсмена. React и Material UI обращаются к FastAPI; постоянные данные хранятся в PostgreSQL. В приложении есть команда, поиск по ФИО, приглашения, недельный календарь, посещаемость, травмы, питание и отчёты.

## Локальный запуск на Linux Mint

```bash
cd server
test -f .env || cp .env.example .env
# Замените JWT_SECRET_KEY в server/.env на случайную строку не короче 32 символов.
docker compose up --build -d
docker compose ps

cd ../client
npm ci
npm run dev
```

Откройте <http://localhost:5173>. FastAPI и Swagger доступны на <http://localhost:8000> и <http://localhost:8000/docs>. Vite перенаправляет `/api` на локальный backend. Используйте в обоих адресах `localhost`, чтобы cookie работала с одним хостом. Контейнер backend применяет миграции при запуске. PostgreSQL доступна только с этого компьютера на порту 15432; данные сохраняются в Docker volume.

Подробная инструкция по `.env`, запуску без Docker, миграциям и тестовой PostgreSQL: [server/README.md](server/README.md).

## Пользовательский сценарий

Зарегистрируйте тренера и спортсмена, указав фамилию, имя, отчество, пароль и роль. После регистрации выполняется вход. Тренер ищет спортсмена по ФИО, выбирает результат и отправляет приглашение. Спортсмен входит в свой аккаунт и принимает приглашение. После этого тренер назначает тренировки, ведёт травмы и питание, отмечает посещаемость; отчёты строятся из данных PostgreSQL. Открепление разрывает связь с тренером и сохраняет историю спортсмена.

Числовые ID остаются внутри PostgreSQL для связей. Клиент использует случайный `public_id` формата UUID, но не показывает его как номер пользователя. Роль и права определяются сервером.

## Архитектура frontend

```text
client/src/
  app/App.tsx                 маршруты, навигация и защита страниц
  pages/                     вход, регистрация, спортсмены, календарь, отчёты
  features/auth.tsx          текущая сессия и профиль
  features/                  приглашения, травмы и питание
  entities/                  типы API и карточка спортсмена
  shared/api/                HTTP-клиент и загрузка данных
  shared/                    тема, даты, поиск и состояния запроса
```

`pages` собирает экраны, `features` реализует действия, `entities` задаёт предметные типы, `shared` содержит переиспользуемые функции. Формы имеют клиентскую валидацию, а сервер дополнительно проверяет запросы. Загрузка, ошибки и пустые состояния отражают реальные ответы API. Демонстрационные данные и переключатель роли удалены из рабочего интерфейса.

Access JWT хранится в памяти вкладки. Refresh token находится в HttpOnly cookie и ротируется сервером; при обновлении страницы клиент восстанавливает сессию через `/auth/refresh`. После выхода frontend очищает профиль, а backend отзывает refresh token. Уже выданный access JWT остаётся действительным до срока истечения, обычно до 30 минут.

## Проверки

```bash
cd client
npm run typecheck
npm run build

cd ../server
uv sync --extra test
uv run pytest tests/unit -v
TEST_DATABASE_URL=postgresql+psycopg://coachtrack:password@localhost:15432/coachtrack_test uv run pytest tests/integration -v
```

Интеграционные тесты используют только отдельную БД с именем, заканчивающимся на `_test`. Сначала создайте её командой из [server/README.md](server/README.md). Для запуска без Docker используйте порт вашего локального PostgreSQL.
