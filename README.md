# CoachTrack

Учебное Fullstack-приложение тренера и спортсмена. Frontend на React и TypeScript пока работает с локальными демонстрационными данными. Backend на FastAPI и PostgreSQL реализован отдельно; интеграция клиента с API запланирована следующим этапом. Новая регистрация принимает фамилию, имя и отчество, а вход выполняется по полному ФИО и паролю. Числовой ID остаётся в БД и JWT для связей и прав доступа.

## Структура

- `client/` — демонстрационный интерфейс, включая поиск по ID/ФИО и локальное удаление спортсмена из команды.
- `server/` — REST API, авторизация, модели SQLAlchemy, миграция Alembic и интеграционные тесты.
- `docs/` — материалы проекта.

## Запуск

Подробная инструкция по PostgreSQL, миграции, серверу, Swagger, API и тестам: [server/README.md](server/README.md).

Frontend:

```bash
cd client
npm install
npm run dev
```

Три основных раздела сохранены: «Спортсмены», «Календарь», «Отчёты». Демо-данные не отправляются в API. Изменения команды существуют только в памяти вкладки и сбрасываются после перезагрузки.

## Лабораторная работа №3 — архитектура frontend и динамический интерфейс

CoachTrack показывает учебный кабинет тренера и спортсмена. Стек интерфейса: React, TypeScript, React Router, Material UI и Vite. Основные маршруты: `/athletes`, `/calendar`, `/reports`, `/login`, `/register`. Неизвестный маршрут перенаправляется на `/athletes`; навигация и кнопка «Назад» браузера работают через React Router.

```text
client/src/
  app/App.tsx                 провайдеры, навигация и маршруты
  pages/                     экраны спортсменов, календаря, отчётов и форм
  features/                  приглашения, роль и общая демо-команда
  entities/                  типы спортсменов/тренировок и карточка спортсмена
  shared/                    исходные данные, поиск, даты, тема и состояния загрузки
```

`pages` собирает экраны из предметных блоков и действий. `features` содержит действия пользователя: приглашение, ответ на него и изменение команды. `entities` задаёт типы данных и карточку спортсмена. `shared` хранит общие утилиты и компоненты. В `features/demoTeam.tsx` один React Context хранит зарегистрированных спортсменов, их связь с тренером и приглашения. `features/demoRole.tsx` хранит выбранную роль и демонстрационного спортсмена. Поэтому приглашение и открепление сразу отражаются в профиле, составе команды, календаре и отчётах.

Демо-данные находятся в `shared/demoData.ts`. Все пользователи имеют ФИО в порядке «Фамилия Имя Отчество». Изначально три спортсмена входят в команду, а Соколова Мария Андреевна (ID 4) не имеет тренера. Переключатель в шапке позволяет выбрать роль, а для роли спортсмена — конкретный профиль. Поиск работает по точному ID и частям ФИО; при неоднозначном имени форма приглашения предлагает выбрать ID. Принятие приглашения создаёт связь в локальном состоянии, отклонение её не создаёт. Удаление из команды разрывает только связь: личные данные, травмы, питание и история тренировок остаются. Данные возвращаются к исходным после обновления страницы.

Формы входа и регистрации проверяют поля на клиенте и показывают сообщения у полей Material UI. Регистрация содержит отдельные поля фамилии, имени и отчества. Демо-вход находит существующий профиль по ФИО и берёт его роль из записи. В демонстрационном React-интерфейсе пароль не проверяется, не сохраняется и не отправляется по сети; учётная запись не создаётся. Настоящий вход по ФИО и паролю работает в Backend и доступен для проверки через Swagger. Экран спортсменов, календарь и отчёты показывают загрузку локальных данных с короткой задержкой. На каждом из этих экранов кнопка «Показать ошибку загрузки» воспроизводит ошибку детерминированно; «Повторить» загружает данные снова. Пустые списки, календарь и нулевая статистика отображаются отдельно. После загрузки содержимое плавно появляется через Material UI `Fade`; стандартный диалог подтверждает удаление спортсмена. React пока не обращается к FastAPI: подключение настоящего API запланировано следующим этапом.

Проверка frontend:

```bash
cd client
npm ci
npm run typecheck
npm run build
npm run dev
```

### Скриншоты лабораторной

Сохраняйте реальные снимки работающего интерфейса в `docs/screenshots/`; пустые изображения не используются. Откройте `http://localhost:5173` после `npm run dev` и снимите:

| Файл | Что открыть |
| --- | --- |
| `login.png`, `register.png` | `/login` и `/register`; для проверки ошибок отправьте пустую форму |
| `trainer-athletes.png` | роль «Тренер», `/athletes`, состав команды и поиск |
| `trainer-calendar.png`, `trainer-reports.png` | роль «Тренер», `/calendar` и `/reports` |
| `athlete-profile.png` | роль «Спортсмен», ID 4, `/athletes`: профиль без тренера |
| `athlete-calendar.png`, `athlete-reports.png` | роль «Спортсмен», ID 1, `/calendar` и `/reports` |
| `loading.png`, `error.png` | обновите `/athletes` и быстро снимите загрузку; затем нажмите «Показать ошибку загрузки» |

Для сценария приглашения под тренером найдите ID 4 и отправьте приглашение, переключитесь на спортсмена ID 4 и примите его. Вернитесь к тренеру: спортсмен появится в команде. Для отклонения обновите страницу и повторите сценарий, выбрав «Отклонить». Для удаления откройте «Подробнее» у спортсмена, проверьте «Отмена», затем подтвердите удаление и сравните календарь и отчёты до и после.
